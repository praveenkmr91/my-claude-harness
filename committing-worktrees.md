# Committing — worktrees (continues `committing.md`)

## Worktrees
- **"Work in a worktree" moves the session, not just the work:** create it, then `EnterWorktree` with its `path`. Carrying commits or files across while the session stays in the shared checkout is not it.
- **Inside a worktree session, plain git from the worktree cwd, one command per call, no chain.** Claude Code refuses git it can't prove stays inside the worktree: `cd` to the shared checkout, `git -C`, loops, subshells, `time -p`, or runtime variables around git.
- **Entering a worktree locks every running subagent to it,** blocking one that writes the shared checkout mid-step. Let it finish before `EnterWorktree`, then move its output with `cp` (test a suspected hook block before rewriting files by hand).
- **A `tsc` / vitest spike enumerating a plan's call sites** runs in a scratch worktree and commits to its own branch there; once that commit exists the worktree is removed, and the plan cites only the commit and branch, with the build in the main checkout.
- **New worktrees branch from local HEAD: `worktree.baseRef: "head"` in `settings.json`,** covering `EnterWorktree`, `--worktree` and an Agent's `isolation: worktree`. Claude Code's default branches from `origin/<default-branch>`, which left an isolated agent's output on a stale base (seen 2026-11-09). The setting is unproven on an isolated agent: on the first such dispatch with unpushed commits, confirm with `git merge-base --is-ancestor <local branch> <agent branch>`; if that fails, create the worktree yourself (`git worktree add -b <branch> <path> <local branch>`) and give the agent that path.
- **Removing a worktree and its branch is one chain naming only that branch:** `git worktree remove <path> && git branch -D <its branch>`. `hooks/block-dangerous-git.sh` passes `-D` only for a branch freed earlier in the same `&&` chain, so splitting the two, or adding any other branch to the `-D`, is blocked; every other branch's `-D` is Praveen's `!`.
- **A session owns the worktree it created with `git worktree add -b`:** there the hook passes `git -C <worktree> reset --hard <ref>` and a `git branch -D` of that branch on its own. A worktree made by `EnterWorktree`'s `name`, or by another session, is not owned; a subagent owns none, and a `cd` or `GIT_*` variable in the command voids it.
