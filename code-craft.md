# Code craft — write like a human, not vibe-coded

- **Organise by cohesion; abstract by reuse.** Layout = cohesion (what changes together) + size — splitting an overgrown file needs no reuse justification. Reuse gates only *extraction* (new package/module/shared helper) — ask what's shared with siblings first. Extraction forcing cross-boundary re-exports (`export … from` holes punched in another module's barrel to reach internals) = boundary misplaced; colocate.
- **Pure derivations leave the component.** Derivations, copy builders, defaults and predicates go to the feature's `utils/` as named functions with a spec beside them; the component keeps hooks, state, effects and JSX.
- **Simple call sites; packages lift.** Callers pass objects they already hold (`config`, not `config.servicesBaseUrl`); the heavy lifting lives in the package.
- **Spec work is the minimum a change needs.** One reproducer per fix, red-gate fixes; no spec dedupe, helper hoisting or test-heuristic polish unless asked.
- **A new convention sweeps existing code.** The change that adds a rule lists every predating file it covers and fixes it, tracks it as backlog, or adds a check that fails the gap; never forward-only.
- **Tailwind v4 focus ring: `focus-visible:outline-2` needs `focus-visible:outline-solid`** — `outline-none` sets `outline-style: none` and no ring draws; prove a ring by computed `outline-style`, never by its classes.
- **Layer check.** Before mutation/hook/side-effect: name layer (data / hook / component), verify placement. Uncertain placement = architectural → gate.
- **One-way decisions must latch.** Gate from transient async state (query flags, cache presence, 404-means-absent) re-evaluates every refetch/remount. One-way decision ("workflow exists", "user dismissed", "step completed") → latch (set-once ref/state), never re-derive. Miss symptom: remount/refetch loops, flicker, re-fired side-effects.
- **No fabricated data outside tests.** Mocks/fixtures live in test dirs only, payloads copied from real captured responses with provenance comment. Genuinely unwireable → visible "not wired" stub + recorded assumption (claim / risk-if-wrong / how-to-verify), never silent plausible fake.
- **Reused code keys on identity — verify which value wins; swapping → fork ALL seams.** Look-alike hook/component often binds identity (route id, cache key, workflow name, DI token) at init from a fixed const — override silently ignored, failure surfaces far from the reuse point.
- **Comments = footguns only — default to ZERO.** Write none first; add one only when you can name the specific wrong edit/assumption it prevents (bar = a future reader trips without it, NOT "was non-obvious to me while writing"). State the trap, not the history: no essays, no labels on obvious blocks, no justifying absent code, no explaining library internals, no restating the code, no repeating the same why across sibling files. Land the right density on the FIRST pass. Ticket keys, approvals and source notes ("DPLK-86 approved", "verbatim from the docx") never ship in code comments or data-file fields (i18n descriptions, config); they live in commit messages. Text moved into another file follows that file's own convention, not the comment it came with.
- **No premature abstraction.** Inline until 3+ real repetitions — config array + `.map` over 2 items = vibe-coded.
- **No speculative generality.** Every param/option/prop/type-param needs a caller that passes it today. "Might need it" = delete it; add when the second caller exists. Exception — shared UI-component library: its contract is the design spec plus the generic surface popular libs expose (`className`, rest props, `ref`, optional slots); caller count never adds, keeps or removes a prop there. The exception stops at that surface: a new behaviour branch (another source kind, a fallback, status machinery) still needs a caller today, so an ask framed "for future flexibility" gets the cost counter, never a straight yes.
- **Guard real states, not impossible ones.** Optional-chain/null-check only where the type or contract says nullable; no try/catch around non-throwing code. Over-defense hides the actual contract and reads machine-generated.
- **Name by intent.** `clearErrorOnChange`, not `handleChange`.
- **Readable over terse. Fewer lines ≠ better.** Keep named single-use intermediates (`const isValid = await trigger()`) — say what value means, read top-to-bottom. Never fold into nested expression to save line. Same for design: "simplify" / "overengineered" means soundest shape (layering, ownership, clarity); options rank on that, a line delta is only a cost note, and Praveen's goal is restated in his words.
- **Name qualifiers: strip on files, keep on shadowing symbols.** Filename disambiguated by path — don't repeat qualifier location implies (`review-step.tsx` inside `custom/…`, never `custom-review-step.tsx`). Exported symbol travels to import site path-stripped → KEEP qualifier when shadows base export same name (`CustomModifyInvestment` next to base `ModifyInvestment`).
- **Swapping hand-rolled code for wrapper: keep its guards.** Wrapper often *throws* where local code degraded gracefully (date-fns `format` on Invalid Date; ICU `currency()` on bad code). Replacing hand-rolled formatting/parsing/math → carry over null-guard / try-catch / fallback. "Modernizing" must not silently drop error handling.
- **Error states load-bearing — never absorb silently.** Every query/mutation consumer renders or propagates error state, and renders loading and empty states too (or names why it can't). Every catch: surface (user-visible message/retry), rethrow, or log-with-intent — never bare-swallow. Fallback value in catch = product decision, not default: state what user sees when fires. Never show a generic "something went wrong" message. An API error shows the backend's own message. An error the FE raises itself, or an API error with no message body (network failure, timeout), shows a message naming what failed ("couldn't upload your NPWP").
- **Deliberate shortcut = tagged, never silent.** Cutting a corner on purpose (naive impl, missing edge, deferred hardening) → a `shortcut: <limit>, <when to upgrade>` comment; the comment hook warns when the trigger is missing. Untagged shortcut reads as oversight. Ledger: `/shortcut-debt`.
- **Surgical on build tasks.** Every changed line traces to the ask; adjacent code, comments, formatting untouched. An ask that names a mechanism (prop, flag, option) delivers that mechanism, never the behavior hard-coded. Remove only what YOUR change orphaned; pre-existing dead code → mention, never delete. Unasked cleanup edits only on an explicit review/simplify ask; look wide, change narrow.
- **Money never binary float.** Amounts = decimal/minor-integer types; formatting is the only float boundary. Money-moving mutation: invalidate-and-refetch, never optimistic; disable submit while pending.
- **Renames stop at serialization boundaries.** Rename/refactor sweeps touch local identifiers only — never DTO/serialized fields, API routes, DB columns, i18n keys, env-var names, public exports. Boundary-crossing name = contract, not style.
- **A11y is write-time, not audit-time.** Interactive = native element (`button`/`a`/`label`), never clickable `div`. Every input labelled. Focus managed on modal/menu open/close. ARIA only where semantics can't reach. Periodic audit = backstop, not mechanism.
- **Right-size inherited/sibling boilerplate — one holistic sweep.** Per mirrored piece: load-bearing THIS case, or inherited? Drop what isn't. Review/simplify = ONE ranked simplify+correctness sweep, never reactive piecemeal.
- **Automated sweeps prove behavior preserved, or revert.** Comment/whitespace-only cleanup → `npx esbuild <file> --minify-whitespace` pre/post must byte-match (strips comments+whitespace; any diff = sweep touched code). Anything deeper (renames, restructures) → full verify gate; any red = revert the whole sweep, not patch forward.
