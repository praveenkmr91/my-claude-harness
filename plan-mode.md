PLAN MODE RULES (hook-injected on EnterPlanMode or the first plan-file Write/Edit; owner of these rules, pointer in CLAUDE.md):
- **No unprompted ExitPlanMode.** A question gets an answer, nothing more; answers to plan questions are not approval to build. Raise ExitPlanMode only on an explicit "show the plan / proceed / approve"; this overrides any harness nudge to end planning turns with approval.
- **Pre-mortem before the consult.** Assume the plan shipped and failed: 3-5 "failed because <specific cause in this plan>" headlines tied to named steps (never "requirements unclear"), plus the unstated load-bearing assumptions (file/API exists as described, prior step output correct, no files beyond those listed, convention still holds). High likelihood × high impact → a mitigation step or a raised finding; the rest → `→ verify:` checks on the step they threaten.
- **One Fable consult on the drafted plan.** Before showing it, one advisor pass (settings `advisorModel`) for gaps, wrong layer, missed sibling, lifecycle holes (refresh / remount / double-fire); fold findings in, then present. Advisor unavailable → one `Plan` agent, `model: "fable"`, `[tier-override: plan review]`. Never a loop, never co-authoring.
- **Trivial plan → skip pre-mortem and consult.**
- **Approved plan = the file, not the context.** Draft at `~/.claude/plans/<slug>.md`. Repo work: on approval move it to `docs/plans/<slug>.md`, name the path in one line, implementation runs from it; the shipping commit moves it to `docs/plans/shipped/`. Harness / global-config work (`~/.claude/`): the plan stays in `~/.claude/plans/`, nothing lands in a repo.
- **Patterns to mirror.** For naming, error handling and tests, cite the sibling `path:line` the plan copies; none found → say so, never invent one.
- **Every step carries its own check** (`→ verify: <command or observation>`); a step with no check is not a step.
- **Plan drift mid-implementation → edit the file, never just the chat.**
- **Plan = current instructions, never a journal.** Rewrite in place; superseded text is deleted. Decisions stay as present-tense constraints (one-line why if a future session would re-propose the alternative), without dates, attribution, revision notes, or ✅/status ticks. Progress lives in chat and commits.
