# Committing

- **Commit locally at verified checkpoints, unasked.** After `review-routing.md`'s done bar passes, pathspec only (below); the Stop gate checks lint and lenses on any committing turn. Push and PR need a yes: `git push` is hook-denied, `gh pr create` hook-asked.
- **Self-review diff through `code-craft.md` lens before commit — required gate, not polish.** Lint + tsc + code-review passing ≠ reading like human. Delete-list first: what can go before what should change. Watch: comment bloat, same *why* stated twice. Inline for small diffs.
- **"Unasked" covers checkpoints of work I asked for, never a check turn.** A review, recheck or question changes nothing, including staging or committing a file I placed. A missing step found there goes in the reply as an offer.
- **Pathspec commits when tree has concurrent in-flight work.** Shared branch carrying staged/unstaged changes from other tasks → commit explicit pathspec (`git commit --only <dir>/`), unrelated work untouched. A pathspec commits whole files: `git diff <file>` shows a hunk that isn't yours → commit a blob of HEAD plus only your hunks via temp-index plumbing. Shared wiring files (package.json, lockfile, routes) → leave to owner.
- **One commit per piece of work; every revision squashes into it.** A plan doc and its build are one piece: each plan revision, step checkpoint and chunk folds into the commit that added the plan, the shipping commit (which deletes the plan) included, never stacked on top. The message is rewritten to describe the work as it now stands. Unpushed history only.
    - My commit is HEAD: re-read HEAD in the same command as the amend (`git log -1 --format=%s | grep -q '<subject>' && git commit --amend --only <paths> …`); a HEAD read earlier in the turn is stale, since a concurrent session's commit can land between.
    - My commit sits below HEAD, only mine above it, clean tree: `git reset --soft <parent of my commit>`, recommit, `git diff --quiet <new> <old>`.
    - Another session's commits sit on top: plumbing, never rebase (the shared tree may hold their uncommitted work). Build each tree in a temp `GIT_INDEX_FILE` with my file's blob swapped in, `commit-tree` mine on its parent and each of theirs on top keeping their author and dates, match each of their diffs by `git patch-id`, then `update-ref` guarded on the old HEAD. Tell the user which shas changed.
    - A child branch lands as one `git merge --squash` commit authored by its main author; never `--no-ff`, never a fast-forward of its commits. "Merge into <branch>" means the local branch, and I land it myself; a push is a separate ask, never handed back.
- **Worktree session: plain git from the worktree cwd.** Claude Code refuses git it can't prove stays inside the worktree — `cd` to the shared checkout, `git -C`, loops, subshells, `time -p`, or runtime variables around git. One plain command per call, no chain.
- **No attribution trailers in commits or PRs.** Enforced by `hooks/block-dangerous-git.sh` (denies `Co-Authored-By` / "Generated with" / tool footers at PreToolUse; a teammate's `@additiv.com` co-author passes); do not copy trailers from `git log`.
