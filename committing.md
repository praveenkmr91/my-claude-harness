# Committing

- **Commit locally at verified checkpoints, unasked.** A checkpoint is work Praveen asked for that has passed `review-routing.md`'s done bar and a `code-craft.md` read of the diff — lint, tsc and review lenses passing is not the same as reading like a human; the Stop gate checks lint and lenses on any committing turn. A review, recheck or question turn on anyone else's work is not a checkpoint: it changes nothing, including staging or committing a file he placed, and a missing step found there goes in the reply as an offer. A bare mid-turn 'approved' answers the open permission prompt, not a commit.
- **Push and PR need a yes.** `git push` is hook-denied, `gh pr create` hook-asked. Never offer a push as the next step. Where a hook says to push, push in that turn; a summary never lists a push as pending.
- **Own unpushed work is mine to fix and fold, review turns included.** Confirmed findings on it: fix, re-verify, squash into the commit (below), report findings and fixes together — never a "yes to which?" list. Still ask only for an architectural or irreversible change (`CLAUDE.md` gate; a helper in an existing layer or a new i18n key is neither) or a fix that reverses a decision Praveen stated. "Own" includes work a subagent or peer session built under my supervision: an approval gate I set in a handoff is mine to clear, never relayed to him.
- **Subject starts with the ticket key** when the work has one: `DPLK-212: feat(account): <summary>`, never a trailing `(DPLK-212)`, even where repo history mixes styles.
- **Commit only my files.** A shared branch carrying staged or unstaged changes from other tasks → explicit pathspec (`git commit --only <dir>/`), unrelated work untouched. A pathspec commits whole files: `git diff <file>` showing a hunk that isn't mine → commit a blob of HEAD plus only my hunks through a temp index (the recipe below). Shared wiring files (package.json, lockfile, routes) → leave to their owner.
- **One commit per piece of work; every revision squashes into it.** A plan doc and its build are one piece: each plan revision, step checkpoint and chunk folds into the commit that added the plan, the shipping commit (which deletes the plan) included, never stacked on top. A piece is the feature, not the plan: a follow-up plan, fix or copy change on an unpushed feature folds into that feature's commit; only work outside the feature (shared core, auth) gets its own. The message is rewritten to describe the work as it now stands. Unpushed history only.
    - My commit is HEAD: re-read HEAD in the same command as the amend (`git log -1 --format=%s | grep -q '<subject>' && git commit --amend --only <paths> …`); a HEAD read earlier in the turn is stale, since a concurrent session's commit can land between.
    - My commit sits below HEAD, only mine above it, clean tree: `git reset --soft <parent of my commit>`, recommit, `git diff --quiet <new> <old>`.
    - Another session's commits sit on top: plumbing, never rebase (the shared tree may hold their uncommitted work). Build each tree in a temp `GIT_INDEX_FILE` with my file's blob swapped in, `commit-tree` mine on its parent and each of theirs on top keeping their author and dates, match each of their diffs by `git patch-id`, then `update-ref` guarded on the old HEAD. Tell Praveen which shas changed.
    - A child branch lands as one `git merge --squash` commit authored by its main author; never `--no-ff`, never a fast-forward of its commits. "Merge into <branch>" means the local branch, and I land it myself.
- **"Undo the commit of X" takes only X out of the commit.** Every other file stays committed, and X's edits stay in the working tree (`git reset HEAD~1 -- X`, then amend); file content changes only when the ask names a revert ("revert", "drop the change", "restore the file"). "But not the edits" scopes what stays, never adds an action.
- **Worktrees.**
    - In a worktree session, plain git from the worktree cwd: Claude Code refuses git it can't prove stays inside the worktree — `cd` to the shared checkout, `git -C`, loops, subshells, `time -p`, or runtime variables around git. One plain command per call, no chain.
    - Entering a worktree locks every running subagent to it, so one writing the shared checkout is blocked mid-step: let it finish before `EnterWorktree`, then move its output with `cp` (test a suspected hook block before rewriting files by hand).
    - A `tsc` / vitest spike that enumerates a plan's call sites runs in a scratch worktree and commits to its own branch there; once that commit exists the worktree is removed, and the plan cites only the commit and branch, with the build in the main checkout.
- **No attribution trailers in commits or PRs** — no `Co-Authored-By`, "Generated with" or tool footer; a teammate's `@additiv.com` co-author is fine. Never copy trailers from `git log`. Enforced by `hooks/block-dangerous-git.sh` and `hooks/commit-trailer-check.sh`.
