# Subagent model tiers — full spec (pointer lives in CLAUDE.md "Model tier by work KIND")

| Work | Tier | Note |
|---|---|---|
| Brain — planning, architecture, design judgment, code review, plan cold reads (`cold-reader`), debugging | Opus: `model: "opus"`, or omit — from a sub-Opus session the hook injects opus rather than letting review run below tier | Sonnet and Haiku are denied for review/planning agents (one exception: a battery Praveen typed as Sonnet). From a Fable session omit `model`: the hook places Opus, or Fable when Praveen asked for it, and a named `opus` would override that ask |
| Review-battery members | Per member, as `~/.claude/review-battery.md` assigns | The one brain-work exception; never above the thread that verifies them |
| Plan execution — code, docs or config for an approved step (a plan file or a design Praveen approved in chat) whose names, prop shapes and paths are already settled; bulk mechanical sweeps | Sonnet, effort `high` → the `implementer` agent | One step or slice per dispatch; `implementer` stops and hands the question back on ambiguity, and an unsettled design call stays on Opus |
| Plan dry runs — a plan's `→ verify:` lines, cited `path:line`s and symbol censuses, reported per step | Sonnet → the `dry-runner` agent | No verdict: the dispatcher judges each result. `checker` keeps named checks, `Plan` keeps consults |
| Purely mechanical — run a named check, listing, grep census, file move | Haiku → the `checker` agent | No design decision, no interpretation of the result. A Haiku negative ("no matches", "no failures") is weak evidence — re-run a decisive one on Sonnet |
| Worker fan-out | Haiku for low-tier slices (listings, grep sweeps, classification); Sonnet for parallel mechanical slices that write code; Opus for any slice that still carries a judgment call | Sonnet never *reviews* code — a worker's "looks fine" is not an oracle |
| Explore | Haiku always | Hook injects it; in Workflow `agent()` (hook-blind) pass `model: "haiku"` — effort sharpens within a tier, never substitutes for one |
| `effort` frontmatter | Frontmatter is the default; `high` on `implementer`, `dry-runner`, `cold-reader`, `adversarial-reviewer`; `medium` on `reuse-analyzer`, `placement-analyzer`, `dfs-lookup`; every other agent, plugin agents and `Plan` included, inherits session effort | A dispatch `effort` overrides the default either way; a session pins one effort for its life, since a top-level effort change invalidates the messages cache (Claude API prompt-caching reference); effort varies through subagents; off `checker` until a run proves Haiku accepts it |

## Policy

- **A subagent cannot ask the user.** `AskUserQuestion` is stripped from every subagent and the missing tool does not error, so a worker told to "ask" or "confirm" picks an answer and reports it as confirmed. A worker ends its turn with the open question in its report and labels any choice it defaulted as defaulted; the dispatcher carries the question to the user, and a brief never says "ask the user" to a subagent.
- **A dispatch on Opus or above names its cost before it starts, and its brief bounds it.** The dispatch line states the model, the expected scale and what caps it. A blind consult (a fresh agent given only the problem, so its answer can be matched against mine, which I write to a file first) gets two or three bounded questions, no full-suite runs, and the cheapest tier that can answer; never an open "account for everything" sweep. One running long is told by SendMessage to report now, never TaskStopped, which discards its findings; "long" is 15 minutes, and I send it then without waiting for Praveen to ask. A debug splits by kind: the reproduction or bisect (seeded replays, ordered runs, instrumentation) goes to a Sonnet worker that reports raw output, and only the fix design stays on Opus.
- **A changed instruction reaches running agents.** An instruction that changes how work runs (target env, server, account, data) goes to each running agent via SendMessage in the same turn; none is left to finish on the old target.
- **Hand-off from an Opus-or-above main thread**: once review findings or a fix list are settled, the remainder (casts, renames, comment fixes, spec helpers, test runs) dispatches — `implementer` for edits, `checker` for verify/e2e — even when the first fix needed Opus. A direct ask from Praveen whose result is already fixed (a named reference to copy such as "follow Hydrogen", an exact element to remove, a class or size change) is a settled fix list too: dispatch it, even when it is one file. A search whose pattern is known (find a file, grep a symbol across repos) follows CLAUDE.md "Direct tool": up to 3 direct calls, then `checker` or Explore. A skip judges the remainder, never the edit in hand, and the only skip is a named open call the plan leaves undecided; size, urgency or already-loaded context never counts, so a "fix that first" ask dispatches before the first source write. An open call ends once I decide it: the skip covers the measuring and deciding, never the edits that carry the decision out (tokens, spec, callers), which dispatch with the decision written into the brief.
- **Reviewing `implementer` output is Opus work**: Opus re-runs lint and tsc itself; `checker` runs tests and a uniformity census (grep counts of old form vs new form) and pastes raw output, which Opus judges; Opus reads one instance of each distinct variant in full plus every hunk the census flags, and the whole diff when the pattern isn't greppable. The reviewer applies its own fixes and re-runs the verify gate after them.
- **External tool work** (MCP servers, external CLIs) is routed by call shape: unbounded → the `external-io` agent (Sonnet) or `fork`, one bounded read inline. Spec `~/.claude/external-io.md`.
- **Advisor exemption**: the harness advisor (`advisorModel` in settings) stays Fable 5.1 and sees the whole transcript, diffs included. It isn't a dispatch, so none of the above governs it, and its effort can't be set. Over an Opus executor its gain on routine work is at the edge of noise for about twice the cost; on a plan it catches what I invent, so it runs before every plan (CLAUDE.md names when). With the main thread on Fable it is the same model reading the same transcript, so neither it nor the Fable `Plan` fallback runs, at any trigger; the cold read stays the independent check on a plan.

### Fable sessions

- **Fable is never the writer.** A Fable main thread writes docs, config and plan files directly and dispatches every source edit to `implementer`; Fable is never placed on `implementer` or any worker, with no override. Its own source writes are lifted for one turn by `[tier-override: <why>]` in the typed prompt. Fable reviews **plans** on its own authority and reviews **code** only on Praveen's say-so (the Fable pool is metered separately; the review tier is Praveen's call, never inherited). Praveen rarely asks unprompted, so the move is mine to propose when a diff earns it — HIGH risk plus bulk, or a finding Opus already missed once — with the cost named; Praveen's yes is the approval. The ask or the yes has to arrive as its own typed prompt: a message sent mid-turn is not stored as a turn.
- **Fable plan consult** goes only onto the `Plan` agent, from an Opus-or-above main thread: for every plan when the advisor is unavailable, and outside plans only when the decision is irreversible, money-moving, or one Opus already got wrong once; `plan-mode.md` owns where in the plan flow it runs. A typed consult ask ("consult fable", "fable opinion") is also dispatched as `Plan`, which cannot write; `general-purpose` can, so Fable on it is denied even with the ask. Ad-hoc shapes need `[tier-override: <why>]`.
- **A worker never dispatches Fable**, not even with a tier-override, and neither does a session below Opus. A worker that wants a Fable opinion finishes what it can and ends its turn with the question for the dispatcher — the decision, the options, what needs ruling on; the dispatcher takes the call.

## Enforcement

Mechanics and escapes live in the hooks' own comments and deny text; this section names only what each hook decides.

- `hooks/enforce-subagent-model.sh` (Agent) denies a dispatch with no `subagent_type`, a model above the session tier (a review/planning agent may name opus), Sonnet or Haiku on a review/planning agent, and Fable outside the Fable rules above. A Fable code review opens only on Praveen's typed ask or a yes to a reply ending `Fable review?` / `Fable battery?`; a passing mention is not an ask. With `model` omitted it places Explore and review agents itself (table above). From an Opus session it denies a model-less `general-purpose`, so `/simplify` and `/security-review` agents, which are review work, are dispatched with `model: "opus"`.
- `hooks/opus-write-nudge.sh` (Write|Edit, main thread, Opus or above) blocks every source write in a Fable session, and an Opus session's first source write of every turn until `implementer` is dispatched. Source means code, not docs or config.
- `hooks/inline-call-nudge.sh` enforces CLAUDE.md "Direct tool": it nudges from the 4th direct lookup since the last typed prompt, agent dispatch or write.
- Everything fail-opens on an unreadable transcript or unknown session model, except Fable, which **fails CLOSED**. `[tier-override: <why>]` lifts any denial deliberately, except a worker reaching for Fable and a dispatch with no `subagent_type`, both unconditional.

## Principle

Use the cheapest tier whose oracle is strong enough for the decision; pay for a higher tier only where a wrong answer is expensive to discover later.
