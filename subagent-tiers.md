# Subagent model tiers — full spec (pointer lives in CLAUDE.md "Model tier by work KIND")

| Work | Tier | Note |
|---|---|---|
| Brain — planning, architecture, design judgment, code review, debugging | Opus: `model: "opus"`, or omit — from a sub-Opus session the hook injects opus rather than letting review run below tier | Sonnet and Haiku are denied outright for review/planning agents; never `model: "opus"` from a Fable session |
| Review-battery members | Per member, as `~/.claude/review-battery.md` assigns | The one brain-work exception; never above the thread that verifies them |
| Mechanical — code, docs or config written to an approved plan | Sonnet, effort `high` → the `implementer` agent | The plan must be prescriptive: a Sonnet worker has only lint/tsc as an oracle, so an ambiguous plan gets guessed at. `implementer` is told to stop and ask instead |
| Purely mechanical — no judgment at all (run a named check, listing, grep census, file move) | Haiku → the `checker` agent | No design decision, no interpretation of the result. A Haiku negative ("no matches", "no failures") is weak evidence — re-run a decisive one higher |
| Worker fan-out | Haiku for the low-tier slices (listings, grep sweeps, classification); Sonnet for parallel mechanical slices that write code; Opus for any slice that still carries a judgment call | Sonnet never *reviews* code — a worker's "looks fine" is not an oracle |
| Explore | Haiku always | Hook injects it; in Workflow `agent()` (hook-blind) pass `model: "haiku"` — effort sharpens within a tier, never substitutes for one |
| `effort` frontmatter | `high` on the Sonnet `implementer` only | A supported key (`low`…`max`), but the docs say available levels depend on the model and name none for Haiku, and say nothing about what an unsupported value does — so it stays off `checker` until a run proves Haiku takes it |
| Haiku | Exploration, listings, classification, named checks, and other no-judgment lookups | Weaker recall than Sonnet: a Haiku "no matches" is not proof of absence — re-run a decisive negative on Sonnet, and keep broad multi-convention sweeps there |

- Fable reviews **plans**, and nothing else. It never writes or rewrites code, and it never reviews code — code review is Opus work. Only an Opus main thread dispatches it, only onto the `Plan` agent (exact match — a glob would hand the costliest tier to any future agent whose name merely contains "plan"), and only when the decision is irreversible, money-moving, or one Opus already got wrong once — normally the plan-mode consult. A worker never dispatches it under any circumstance — not even with a tier-override — and neither does a session below Opus. A worker that wants a Fable opinion finishes what it can and ends its turn with the question for the dispatcher (decision, options, what needs ruling on); the dispatcher takes the call. One accountable decision-maker per consult, and the escalation reason stays where the context is. Ad-hoc shapes (a consult as `general-purpose`) need `[tier-override: <why>]` so the reason travels with the dispatch.
- `hooks/enforce-subagent-model.sh` denies escalation above session tier, Sonnet or Haiku on a review/planning agent (`Plan`, `*review*`, `*analyzer*`, `*simplifier*`, `*silent-failure*`, `*adversarial*`), and Fable from a worker, from a non-Opus session, or onto any agent but `Plan`. It also places two omitted-model dispatches rather than letting them inherit: `Explore` → Haiku, and a review/planning agent from a sub-Opus session → Opus.
- `hooks/opus-write-nudge.sh` is the advisory arm on the main thread, which no PreToolUse gate can observe: from an Opus-or-above session it fires once, on the third distinct file that thread has written itself, pointing the remaining prescriptive work at `implementer`. It nudges and never blocks — the edit has already landed, one or two files is the rule's own escape, and a subagent is skipped outright.
- Everything fail-opens on an unreadable transcript or unknown session model, except Fable, which **fails CLOSED** — the costliest tier must not be reachable by way of an unknown session tier. `[tier-override: <why>]` lifts any denial deliberately, except a worker reaching for Fable, which is unconditional.

## Why the ladder exists

Token burn, not capability theatre. The default failure is silent inheritance: a dispatch with `model` omitted runs at the session tier, so ad-hoc mechanical work quietly costs Opus. Inference from `subagent_type` reaches exactly two kinds, and the hook places those: `Explore` → Haiku, a review/planning agent from a sub-Opus session → Opus. Everything else inherits, because a blind downgrade would put a code-writing worker below tier invisibly — so **the saving comes from dispatching a declared agent** (`implementer`, `checker`, `Explore`) rather than an unqualified `general-purpose`. The main thread is the same leak wearing a different hat: an Opus session that types the edit itself pays the top tier for keystrokes, so its default move on mechanical work is to specify and dispatch, keeping only the verdict and the verify gate. Reach for the cheapest tier whose oracle is strong enough for the decision at hand, and pay for a higher tier only where a wrong answer is expensive to discover later.
