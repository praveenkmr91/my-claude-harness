# Subagent model tiers — full spec (pointer lives in CLAUDE.md "Model tier by work KIND")

| Work | Tier | Note |
|---|---|---|
| Brain — planning, architecture, design judgment, code review, plan cold reads (`cold-reader`), debugging | Opus: `model: "opus"`, or omit — from a sub-Opus session the hook injects opus rather than letting review run below tier | Sonnet and Haiku are denied for review/planning agents (one exception: a battery Praveen typed as Sonnet); never `model: "opus"` from a Fable session |
| Review-battery members | Per member, as `~/.claude/review-battery.md` assigns | The one brain-work exception; never above the thread that verifies them |
| Plan execution — code, docs or config for an approved plan step whose names, prop shapes and paths the plan already settles, a plan file or a design Praveen approved in chat alike; bulk mechanical sweeps | Sonnet, effort `high` → the `implementer` agent | One step or slice per dispatch; `implementer` stops and hands the question back on ambiguity, and an unsettled design call stays on Opus |
| Plan dry runs — a plan's `→ verify:` lines, cited `path:line`s and symbol censuses, reported per step | Sonnet → the `dry-runner` agent | No verdict: the dispatcher judges each result. `checker` keeps named checks, `Plan` keeps consults |
| Purely mechanical — run a named check, listing, grep census, file move | Haiku → the `checker` agent | No design decision, no interpretation of the result. A Haiku negative ("no matches", "no failures") is weak evidence — re-run a decisive one on Sonnet |
| Worker fan-out | Haiku for low-tier slices (listings, grep sweeps, classification); Sonnet for parallel mechanical slices that write code; Opus for any slice that still carries a judgment call | Sonnet never *reviews* code — a worker's "looks fine" is not an oracle |
| Explore | Haiku always | Hook injects it; in Workflow `agent()` (hook-blind) pass `model: "haiku"` — effort sharpens within a tier, never substitutes for one |
| `effort` frontmatter | `high` on the Sonnet `implementer` and `dry-runner`; `medium` on the multi-hop battery lenses `reuse-analyzer` and `placement-analyzer` (a stated review effort raises them) | Single-pass lenses stay at session effort; off `checker` until a run proves Haiku accepts it |

## Policy

- **A subagent cannot ask the user.** `AskUserQuestion` is stripped from every subagent and the missing tool does not error, so a worker told to "ask" or "confirm" picks an answer and reports it as confirmed. A worker ends its turn with the open question in its report and labels any choice it defaulted as defaulted; the dispatcher carries the question to the user, and a brief never says "ask the user" to a subagent.
- **Hand-off from an Opus-or-above main thread**: once review findings or a fix list are settled, the remainder (casts, renames, comment fixes, spec helpers, test runs) dispatches — `implementer` for edits, `checker` for verify/e2e — even when the first fix needed Opus. A direct ask from Praveen whose result is already fixed (a named reference to copy such as "follow Hydrogen", an exact element to remove, a class or size change) is a settled fix list too: dispatch it, even when it is one file. A search whose pattern is known (find a file, grep a symbol across repos) goes to `checker` or Explore, never inline. A skip judges the remainder, never the edit in hand, and the only skip is a named open call the plan leaves undecided; size, urgency or already-loaded context never counts, so a "fix that first" ask dispatches before the first source write. An open call ends once I decide it: the skip covers the measuring and deciding, never the edits that carry the decision out (tokens, spec, callers), which dispatch with the decision written into the brief.
- **Reviewing `implementer` output is Opus work**: Opus re-runs lint and tsc itself; `checker` runs tests and a uniformity census (grep counts of old form vs new form) and pastes raw output, which Opus judges; Opus reads one instance of each distinct variant in full plus every hunk the census flags, and the whole diff when the pattern isn't greppable. The reviewer applies its own fixes and re-runs the verify gate after them.
- **External tool work** (MCP servers, external CLIs) is routed by call shape: unbounded → the `external-io` agent (Sonnet) or `fork`, one bounded read inline. Spec `~/.claude/external-io.md`.
- **Advisor exemption**: the harness advisor (`advisorModel` in settings) stays Fable 5.1 and sees the whole transcript, diffs included. It isn't a dispatch, so none of the above governs it, and its effort can't be set. Over an Opus executor its gain is at the edge of noise for about twice the cost, which is why CLAUDE.md limits when it runs.

### Fable sessions

- **Fable is never the writer.** A Fable main thread writes docs, config and plan files directly and dispatches every source edit to `implementer`; Fable is never placed on `implementer` or any worker, with no override. Its own source writes are lifted for one turn by `[tier-override: <why>]` in the typed prompt. Fable reviews **plans** on its own authority and reviews **code** only on Praveen's say-so (the Fable pool is metered separately; the review tier is his call, never inherited). He rarely asks unprompted, so the move is mine to propose when a diff earns it — HIGH risk plus bulk, or a finding Opus already missed once — with the cost named; his yes is the approval. The ask or the yes has to arrive as its own typed prompt: a message sent mid-turn is not stored as a turn.
- **Fable plan consult** goes only onto the `Plan` agent, from an Opus-or-above main thread, and only when the decision is irreversible, money-moving, or one Opus already got wrong once. It is the fallback when the advisor is unavailable; `plan-mode.md` owns where in the plan flow it runs. A typed consult ask ("consult fable", "fable opinion") is also dispatched as `Plan`, which cannot write; `general-purpose` can, so Fable on it is denied even with the ask. Ad-hoc shapes need `[tier-override: <why>]`.
- **A worker never dispatches Fable**, not even with a tier-override, and neither does a session below Opus. A worker that wants a Fable opinion finishes what it can and ends its turn with the question for the dispatcher — the decision, the options, what needs ruling on; the dispatcher takes the call.

## Enforcement

Mechanics and escapes live in the hooks' own comments and deny text; this section names only what each hook decides.

- `hooks/enforce-subagent-model.sh` (PreToolUse on Agent) denies a dispatch with no `subagent_type`, escalation above the session tier (except a review/planning agent naming opus); Sonnet or Haiku on a review/planning agent (`Plan`, `*review*`, `*analyzer*`, `*simplifier*`, `*silent-failure*`, `*adversarial*`, `*cold-reader*`), except Sonnet on a non-`Plan` one when the last typed user turn says `sonnet battery` / `battery sonnet`; and Fable from a worker, from a sub-Opus session, or onto any agent but `Plan` unless the agent is a review one and the last typed user turn carries the ask (a reserved bigram such as `fable review` / `fable battery`, or a yes to a reply ending a sentence with `Fable review?` / `Fable battery?`). A passing mention on either side is not an ask. With model omitted it places the dispatch rather than letting it inherit: `Explore` → Haiku; a review/planning agent from a sub-Opus session → Opus; any agent from a Fable session → Opus (`/simplify` and `/security-review` fan out model-less `general-purpose` agents).
- `hooks/opus-write-nudge.sh` (Write|Edit PreToolUse, main thread only, Opus-or-above) enforces the hand-off rule: a Fable session gets every source write blocked; an Opus session gets its first source write of every turn blocked until `implementer` is dispatched in that turn or the turn states `implementer: skip — open call: <item>`. `[tier-override: <why>]` in the last typed prompt lifts either for that turn. Source means code, not docs or config; shell-side writes (`sed -i`) are an open gap `bash-write-guard.js` lets through.
- `hooks/inline-call-nudge.sh` (PostToolUse on Read|Grep|Glob|Bash, main thread only, every tier) enforces the CLAUDE.md "Direct tool" rule: from the 4th direct lookup since the last typed prompt, agent dispatch or write, and every 4th after, it nudges to `Explore` or `checker` until one is dispatched or the turn states `direct: continue — <why the target is known>`. A Bash counts only when its first command word is a lookup (`grep`, `rg`, `find`, `ls`, `cat`, `git log` …); a build, verify or commit Bash is not one.
- Everything fail-opens on an unreadable transcript or unknown session model, except Fable, which **fails CLOSED**. `[tier-override: <why>]` lifts any denial deliberately, except a worker reaching for Fable and a dispatch with no `subagent_type`, both unconditional.

## Principle

Use the cheapest tier whose oracle is strong enough for the decision; pay for a higher tier only where a wrong answer is expensive to discover later.
