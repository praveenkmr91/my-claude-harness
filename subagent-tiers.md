# Subagent model tiers — full spec (pointer lives in CLAUDE.md "Model tier by work KIND")

| Work | Tier | Note |
|---|---|---|
| Brain — planning, architecture, design judgment, code review, debugging | Opus: `model: "opus"`, or omit — from a sub-Opus session the hook injects opus rather than letting review run below tier | Sonnet and Haiku are denied outright for review/planning agents; never `model: "opus"` from a Fable session |
| Review-battery members | Per member, as `~/.claude/review-battery.md` assigns | The one brain-work exception; never above the thread that verifies them |
| Plan execution — code, docs or config for an approved plan step whose names, prop shapes and paths the plan already settles; bulk mechanical sweeps | Sonnet, effort `high` → the `implementer` agent | One step or slice per dispatch; `implementer` stops and asks on ambiguity, and an unsettled design call stays on Opus |
| Purely mechanical — no judgment at all (run a named check, listing, grep census, file move) | Haiku → the `checker` agent | No design decision, no interpretation of the result. A Haiku negative ("no matches", "no failures") is weak evidence — Haiku recalls less than Sonnet, so re-run a decisive one on Sonnet |
| Worker fan-out | Haiku for the low-tier slices (listings, grep sweeps, classification); Sonnet for parallel mechanical slices that write code; Opus for any slice that still carries a judgment call | Sonnet never *reviews* code — a worker's "looks fine" is not an oracle |
| Explore | Haiku always | Hook injects it; in Workflow `agent()` (hook-blind) pass `model: "haiku"` — effort sharpens within a tier, never substitutes for one |
| `effort` frontmatter | `high` on the Sonnet `implementer` and on the multi-hop battery lenses `reuse-analyzer` and `placement-analyzer` | Single-pass lenses stay at session effort; off `checker` until a run proves Haiku accepts it |

- Fable never writes or rewrites code: no `implementer`, no worker, no override. Fable reviews **plans** on its own authority, and reviews **code** only on Praveen's say-so (2026-10-14; the Fable pool is metered separately, but the review tier is his call, never inherited). He will rarely ask for it unprompted, so the move is mine to propose when a diff earns it (HIGH risk plus bulk, or a finding Opus already missed once), with the cost named, and his yes is the approval. The hook reads the transcript: a review agent dispatched from a Fable session with model omitted is placed on Opus unless his last typed turn contains a reserved bigram, `fable review`, `fable battery`, `fable consult`, `fable opinion` or `consult fable` (any case), or approves a reply that ends a sentence with `Fable review?` or `Fable battery?` (a passing mention on either side, even "Fable-review gate", is not an ask), and an explicit `model: "fable"` on a review agent passes only on that same condition. A message sent mid-turn is not stored as a turn, so the ask or yes has to arrive as its own prompt. The plan consult is dispatched only onto the `Plan` agent (exact match, never a glob), from an Opus-or-above main thread, and only when the decision is irreversible, money-moving, or one Opus already got wrong once; the plan-mode consult itself is the advisor (next bullet), and this dispatch is its fallback when the advisor is unavailable. A worker never dispatches it under any circumstance — not even with a tier-override — and neither does a session below Opus. A worker that wants a Fable opinion finishes what it can and ends its turn with the question for the dispatcher (decision, options, what needs ruling on); the dispatcher takes the call. A typed consult ask ("consult fable", "fable opinion") is dispatched as `Plan`, which cannot write; `general-purpose` can, so Fable on it is denied even with the ask (2026-10-14: "/consult fable" bounced for that reason). Ad-hoc shapes need `[tier-override: <why>]`.
- Exemption: the harness advisor (`advisorModel` in settings) stays Fable 5.1 and sees the whole transcript, diffs included. It isn't a dispatch, so the rules above don't govern it. Its effort can't be set. Over a Fable session it mirrors the session, and over an Opus 5.5 executor its gain is at the edge of noise (+1.7 points for ~2.1× cost, Anthropic "Optimizing for cost and intelligence"), which is why CLAUDE.md limits when it runs.
- `hooks/enforce-subagent-model.sh` denies escalation above session tier (except a review/planning agent naming opus, the dispatch it already places when model is omitted), Sonnet or Haiku on a review/planning agent (`Plan`, `*review*`, `*analyzer*`, `*simplifier*`, `*silent-failure*`, `*adversarial*`), and Fable from a worker, from a sub-Opus session, or onto any agent but `Plan` unless the agent is a review one and the last typed user turn contains `fable review` / `fable battery`, or approves a reply carrying `Fable review?` / `Fable battery?`. It also places three omitted-model dispatches rather than letting them inherit: `Explore` → Haiku, a review/planning agent from a sub-Opus session → Opus, and a review/planning agent from a Fable session without a Fable ask → Opus.
- Reviewing `implementer` output is Opus work: Opus re-runs lint and tsc itself; `checker` runs tests and a uniformity census (grep counts of old form vs new form) and pastes raw output, which Opus judges; Opus reads one instance of each distinct variant in full plus every hunk the census flags, and reads the whole diff when the pattern isn't greppable. The reviewer applies its own fixes and re-runs the verify gate after them.
- External tool work (any MCP server or external CLI — Jira, Figma, Chrome DevTools are examples, not the list) is routed by call shape, never by a guess at payload size. Unbounded calls run on a worker — comment threads, JQL or CQL search, any listing, Figma file or node reads, all browser work, multi-call pulls: the `external-io` agent (Sonnet; the dispatcher checks any geometry or field names it distils against the saved raw slice), or `fork` for an ad-hoc job (session tier, full context). One bounded read stays inline — a single issue with `fields` restricted and no comments, one account-ID lookup, one schema load — because a spawn costs more than that payload and returns a summary where the source was wanted; a read that asks for comments or lists is unbounded even when this instance happens to be small. The dispatcher passes a scratchpad path for saved slices; a raw sample code will depend on comes back as a saved file, never a summary; outward writes are approved on the main thread first and the worker executes only that exact payload; one browser worker at a time. A worker's classifier denial is never retried by relaying "user approved" over SendMessage — the classifier reads that as Auto-Mode Bypass; the main thread runs that one step itself, where the user approves it directly, then resumes the worker.
- `hooks/opus-write-nudge.sh` is the advisory arm on the main thread: from an Opus-or-above session it fires on the sixth distinct source file (not docs or config) that thread has written itself, and again on the fifteenth unless `implementer` was dispatched, asking whether the remaining work is bulk mechanical enough to hand off. Its `pre` arm (PreToolUse) acts at file zero. From a Fable session it blocks every source write outright with no exit, since Fable never writes code; docs, config and plan files stay direct, and shell-side writes (`sed -i`) are an open gap that `bash-write-guard.js` lets through. From Opus, when a typed prompt says implement or execute next to a `plans/*.md` path and no `implementer` was dispatched, it blocks every source write; a plain retry stays blocked. Its only exit besides a dispatch is a line in the current turn reading `implementer: skip — open call: <the item the plan leaves open>`. That line is self-attested, and size or already-loaded context never counts as an open call (2026-10-11, DPLK-173: "again u doing this"). The `post` arm asks for `implementer: dispatching` or `implementer: skip — <reason>` in the reply, so a skip is visible; it nudges after the write and skips subagents. A skip judges the remainder, not the edit in hand: once review findings or a fix list are settled, the rest (casts, renames, comment fixes, spec helpers, test runs) dispatches — `implementer` for edits, `checker` for verify/e2e — even when the first fix needed Opus. 2026-10-07: "why do u always forget to honor subagent tier rules".
- Everything fail-opens on an unreadable transcript or unknown session model, except Fable, which **fails CLOSED**. `[tier-override: <why>]` lifts any denial deliberately, except a worker reaching for Fable, which is unconditional.

## Principle

Use the cheapest tier whose oracle is strong enough for the decision; pay for a higher tier only where a wrong answer is expensive to discover later.
