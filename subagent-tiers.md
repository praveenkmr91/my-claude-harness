# Subagent model tiers — full spec (pointer lives in CLAUDE.md "Model tier by work KIND")

| Work | Tier | Note |
|---|---|---|
| Brain — planning, architecture, design judgment, code review, debugging | Opus: `model: "opus"`, or omit — from a sub-Opus session the hook injects opus rather than letting review run below tier | Sonnet and Haiku are denied outright for review/planning agents; never `model: "opus"` from a Fable session |
| Review-battery members | Per member, as `~/.claude/review-battery.md` assigns | The one brain-work exception; never above the thread that verifies them |
| Bulk mechanical — code, docs or config written to an approved plan whose plan is much shorter than its diff | Sonnet, effort `high` → the `implementer` agent | The plan must be prescriptive; `implementer` stops and asks on ambiguity |
| Purely mechanical — no judgment at all (run a named check, listing, grep census, file move) | Haiku → the `checker` agent | No design decision, no interpretation of the result. A Haiku negative ("no matches", "no failures") is weak evidence — re-run a decisive one higher |
| Worker fan-out | Haiku for the low-tier slices (listings, grep sweeps, classification); Sonnet for parallel mechanical slices that write code; Opus for any slice that still carries a judgment call | Sonnet never *reviews* code — a worker's "looks fine" is not an oracle |
| Explore | Haiku always | Hook injects it; in Workflow `agent()` (hook-blind) pass `model: "haiku"` — effort sharpens within a tier, never substitutes for one |
| `effort` frontmatter | `high` on the Sonnet `implementer` only | Off `checker` until a run proves Haiku accepts it |
| Haiku | Exploration, listings, classification, named checks, and other no-judgment lookups | Weaker recall than Sonnet: a Haiku "no matches" is not proof of absence — re-run a decisive negative on Sonnet, and keep broad multi-convention sweeps there |

- Fable reviews **plans**, and nothing else. It never writes or rewrites code, and it never reviews code — code review is Opus work. Only an Opus main thread dispatches it, only onto the `Plan` agent (exact match, never a glob), and only when the decision is irreversible, money-moving, or one Opus already got wrong once — normally the plan-mode consult. A worker never dispatches it under any circumstance — not even with a tier-override — and neither does a session below Opus. A worker that wants a Fable opinion finishes what it can and ends its turn with the question for the dispatcher (decision, options, what needs ruling on); the dispatcher takes the call. Ad-hoc shapes (a consult as `general-purpose`) need `[tier-override: <why>]`.
- `hooks/enforce-subagent-model.sh` denies escalation above session tier, Sonnet or Haiku on a review/planning agent (`Plan`, `*review*`, `*analyzer*`, `*simplifier*`, `*silent-failure*`, `*adversarial*`), and Fable from a worker, from a non-Opus session, or onto any agent but `Plan`. It also places two omitted-model dispatches rather than letting them inherit: `Explore` → Haiku, and a review/planning agent from a sub-Opus session → Opus.
- Reviewing `implementer` output is Opus work: `checker` runs lint, tsc, tests and a uniformity census (grep counts of old form vs new form) and pastes raw output, which Opus judges; Opus reads one instance of each distinct variant in full plus every hunk the census flags, and reads the whole diff when the pattern isn't greppable. The reviewer applies its own fixes and re-runs the verify gate after them.
- External tool work (any MCP server or external CLI — Jira, Figma, Chrome DevTools are examples, not the list) runs on an Opus worker when its payload would bloat main context — multi-call pulls, file-wide Figma reads, browser verification: ad-hoc via `fork`, repeated jobs via the `external-io` agent. Single small lookups stay inline — a spawn costs more than their payload; the dispatcher passes a scratchpad path for saved slices; a raw sample code will depend on comes back as a saved file, never a summary; outward writes are approved on the main thread first and the worker executes only that exact payload; one browser worker at a time.
- `hooks/opus-write-nudge.sh` is the advisory arm on the main thread: from an Opus-or-above session it fires once, on the sixth distinct file that thread has written itself, asking whether the remaining work is bulk mechanical enough to hand to `implementer`. It nudges, never blocks, and skips subagents.
- Everything fail-opens on an unreadable transcript or unknown session model, except Fable, which **fails CLOSED**. `[tier-override: <why>]` lifts any denial deliberately, except a worker reaching for Fable, which is unconditional.

## Principle

Use the cheapest tier whose oracle is strong enough for the decision; pay for a higher tier only where a wrong answer is expensive to discover later.
