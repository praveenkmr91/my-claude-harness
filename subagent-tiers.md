# Subagent model tiers — full spec (pointer lives in CLAUDE.md "Model tier by work KIND")

| Work | Tier | Note |
|---|---|---|
| Brain — planning, architecture, design judgment, code review, debugging | Opus: `model: "opus"`, or omit — from a sub-Opus session the hook injects opus rather than letting review run below tier | Sonnet and Haiku are denied outright for review/planning agents; never `model: "opus"` from a Fable session |
| Review-battery members | Per member, as `~/.claude/review-battery.md` assigns | The one brain-work exception; never above the thread that verifies them |
| Plan execution — code, docs or config for an approved plan step whose names, prop shapes and paths the plan already settles; bulk mechanical sweeps | Sonnet, effort `high` → the `implementer` agent | One step or slice per dispatch; `implementer` stops and asks on ambiguity, and an unsettled design call stays on Opus |
| Purely mechanical — no judgment at all (run a named check, listing, grep census, file move) | Haiku → the `checker` agent | No design decision, no interpretation of the result. A Haiku negative ("no matches", "no failures") is weak evidence — Haiku recalls less than Sonnet, so re-run a decisive one on Sonnet |
| Worker fan-out | Haiku for the low-tier slices (listings, grep sweeps, classification); Sonnet for parallel mechanical slices that write code; Opus for any slice that still carries a judgment call | Sonnet never *reviews* code — a worker's "looks fine" is not an oracle |
| Explore | Haiku always | Hook injects it; in Workflow `agent()` (hook-blind) pass `model: "haiku"` — effort sharpens within a tier, never substitutes for one |
| `effort` frontmatter | `high` on the Sonnet `implementer` only | Off `checker` until a run proves Haiku accepts it |

- Fable reviews **plans**, and nothing else. It never writes or rewrites code, and it never reviews code — code review is Opus work. Only an Opus main thread dispatches it, only onto the `Plan` agent (exact match, never a glob), and only when the decision is irreversible, money-moving, or one Opus already got wrong once. The plan-mode consult itself is the advisor (next bullet); this dispatch is its fallback when the advisor is unavailable. A worker never dispatches it under any circumstance — not even with a tier-override — and neither does a session below Opus. A worker that wants a Fable opinion finishes what it can and ends its turn with the question for the dispatcher (decision, options, what needs ruling on); the dispatcher takes the call. Ad-hoc shapes (a consult as `general-purpose`) need `[tier-override: <why>]`.
- Exemption: the harness advisor (`advisorModel` in settings) stays Fable 5.1 and sees the whole transcript, diffs included. It isn't a dispatch, so the rules above don't govern it. Its effort can't be set, and an Opus 5.5 advisor would mirror the Opus 5.5 medium session.
- `hooks/enforce-subagent-model.sh` denies escalation above session tier, Sonnet or Haiku on a review/planning agent (`Plan`, `*review*`, `*analyzer*`, `*simplifier*`, `*silent-failure*`, `*adversarial*`), and Fable from a worker, from a non-Opus session, or onto any agent but `Plan`. It also places two omitted-model dispatches rather than letting them inherit: `Explore` → Haiku, and a review/planning agent from a sub-Opus session → Opus.
- Reviewing `implementer` output is Opus work: Opus re-runs lint and tsc itself; `checker` runs tests and a uniformity census (grep counts of old form vs new form) and pastes raw output, which Opus judges; Opus reads one instance of each distinct variant in full plus every hunk the census flags, and reads the whole diff when the pattern isn't greppable. The reviewer applies its own fixes and re-runs the verify gate after them.
- External tool work (any MCP server or external CLI — Jira, Figma, Chrome DevTools are examples, not the list) runs on a worker when its payload would bloat main context — multi-call pulls, file-wide Figma reads, browser verification: the `external-io` agent (always Opus), or `fork` for an ad-hoc job (session tier, full context). Single small lookups stay inline — a spawn costs more than their payload; the dispatcher passes a scratchpad path for saved slices; a raw sample code will depend on comes back as a saved file, never a summary; outward writes are approved on the main thread first and the worker executes only that exact payload; one browser worker at a time.
- `hooks/opus-write-nudge.sh` is the advisory arm on the main thread: from an Opus-or-above session it fires once, on the sixth distinct file that thread has written itself, asking whether the remaining work is bulk mechanical enough to hand to `implementer`. It nudges, never blocks, and skips subagents.
- Everything fail-opens on an unreadable transcript or unknown session model, except Fable, which **fails CLOSED**. `[tier-override: <why>]` lifts any denial deliberately, except a worker reaching for Fable, which is unconditional.

## Principle

Use the cheapest tier whose oracle is strong enough for the decision; pay for a higher tier only where a wrong answer is expensive to discover later.
