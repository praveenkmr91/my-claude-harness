# Subagent model tiers — full spec (pointer lives in CLAUDE.md "Model tier by work KIND")

| Work | Tier | Note |
|---|---|---|
| Brain — planning, architecture, design judgment, code review, debugging | Opus: `model: "opus"`, or omit — from a sub-Opus session the hook injects opus rather than letting review run below tier | Sonnet and Haiku are denied outright for review/planning agents; never `model: "opus"` from a Fable session |
| Review-battery members | Per member, as `~/.claude/review-battery.md` assigns | The one brain-work exception; never above the thread that verifies them |
| Plan execution — code, docs or config for an approved plan step whose names, prop shapes and paths the plan already settles; bulk mechanical sweeps | Sonnet, effort `high` → the `implementer` agent | One step or slice per dispatch; `implementer` stops and asks on ambiguity, and an unsettled design call stays on Opus |
| Purely mechanical — run a named check, listing, grep census, file move | Haiku → the `checker` agent | No design decision, no interpretation of the result. A Haiku negative ("no matches", "no failures") is weak evidence — re-run a decisive one on Sonnet |
| Worker fan-out | Haiku for low-tier slices (listings, grep sweeps, classification); Sonnet for parallel mechanical slices that write code; Opus for any slice that still carries a judgment call | Sonnet never *reviews* code — a worker's "looks fine" is not an oracle |
| Explore | Haiku always | Hook injects it; in Workflow `agent()` (hook-blind) pass `model: "haiku"` — effort sharpens within a tier, never substitutes for one |
| `effort` frontmatter | `high` on the Sonnet `implementer` and on the multi-hop battery lenses `reuse-analyzer` and `placement-analyzer` | Single-pass lenses stay at session effort; off `checker` until a run proves Haiku accepts it |

## Policy

- **Fable never writes or rewrites code**: no `implementer`, no worker, no override. Fable reviews **plans** on its own authority and reviews **code** only on Praveen's say-so (2026-10-14: the Fable pool is metered separately, but the review tier is his call, never inherited). He rarely asks unprompted, so the move is mine to propose when a diff earns it — HIGH risk plus bulk, or a finding Opus already missed once — with the cost named; his yes is the approval. The ask or the yes has to arrive as its own typed prompt: a message sent mid-turn is not stored as a turn.
- **Fable plan consult** goes only onto the `Plan` agent, from an Opus-or-above main thread, and only when the decision is irreversible, money-moving, or one Opus already got wrong once. The plan-mode consult itself is the advisor (below); this dispatch is the fallback when the advisor is unavailable. A typed consult ask ("consult fable", "fable opinion") is also dispatched as `Plan`, which cannot write; `general-purpose` can, so Fable on it is denied even with the ask (2026-10-14: "/consult fable" bounced for that reason). Ad-hoc shapes need `[tier-override: <why>]`.
- **A worker never dispatches Fable**, not even with a tier-override, and neither does a session below Opus. A worker that wants a Fable opinion finishes what it can and ends its turn with the question for the dispatcher — the decision, the options, what needs ruling on; the dispatcher takes the call.
- **Hand-off from an Opus-or-above main thread**: once review findings or a fix list are settled, the remainder (casts, renames, comment fixes, spec helpers, test runs) dispatches — `implementer` for edits, `checker` for verify/e2e — even when the first fix needed Opus. A skip judges the remainder, never the edit in hand, and the only skip is a named open call the plan leaves undecided; size or already-loaded context never counts (2026-10-11, DPLK-173). An open call ends once I decide it: the skip covers the measuring and deciding, never the edits that carry the decision out (tokens, spec, callers), which dispatch with the decision written into the brief (2026-10-07, 2026-10-15: both times he had to ask why `implementer` wasn't used). From a Fable session, source writes are never direct; docs, config and plan files are.
- **Reviewing `implementer` output is Opus work**: Opus re-runs lint and tsc itself; `checker` runs tests and a uniformity census (grep counts of old form vs new form) and pastes raw output, which Opus judges; Opus reads one instance of each distinct variant in full plus every hunk the census flags, and the whole diff when the pattern isn't greppable. The reviewer applies its own fixes and re-runs the verify gate after them.
- **External tool work** (MCP servers, external CLIs) is routed by call shape: unbounded → the `external-io` agent (Sonnet) or `fork`, one bounded read inline. Spec `~/.claude/external-io.md`, injected on the first MCP call.
- **Advisor exemption**: the harness advisor (`advisorModel` in settings) stays Fable 5.1 and sees the whole transcript, diffs included. It isn't a dispatch, so none of the above governs it, and its effort can't be set. Over a Fable session it mirrors the session; over an Opus 5.5 executor its gain is at the edge of noise (+1.7 points for ~2.1× cost, Anthropic "Optimizing for cost and intelligence"), which is why CLAUDE.md limits when it runs.

## Enforcement (mechanics and escapes live in the hooks' own comments and deny text)

- `hooks/enforce-subagent-model.sh` (PreToolUse on Agent) denies escalation above the session tier (except a review/planning agent naming opus); Sonnet or Haiku on a review/planning agent (`Plan`, `*review*`, `*analyzer*`, `*simplifier*`, `*silent-failure*`, `*adversarial*`); and Fable from a worker, from a sub-Opus session, or onto any agent but `Plan` unless the agent is a review one and the last typed user turn carries the ask — a reserved bigram such as `fable review` / `fable battery` (full list in the hook), or a yes to a reply that ends a sentence with `Fable review?` / `Fable battery?`. A passing mention on either side ("Fable-review gate") is not an ask, and an explicit `model: "fable"` on a review agent passes only on that same condition. With model omitted it places four dispatches rather than letting them inherit: `Explore` → Haiku; a review/planning agent from a sub-Opus session → Opus; a review/planning agent from a Fable session without the ask → Opus; any other agent from a Fable session → Opus (2026-10-14: `/simplify` and `/security-review` fan out model-less `general-purpose` agents).
- `hooks/opus-write-nudge.sh` (Write|Edit, main thread only, Opus-or-above) enforces the hand-off rule. `pre`: a Fable session gets every source write blocked with no exit; an Opus session executing a `plans/*.md` path (typed implement/execute prompt) gets source writes blocked until `implementer` is dispatched or the turn states `implementer: skip — open call: <item>` (self-attested; a plain retry stays blocked). `post`: nudges on the sixth and fifteenth distinct source file this thread wrote unless `implementer` was dispatched, asking for `implementer: dispatching` or `implementer: skip — <reason>` in the reply so the skip is visible. Source means code, not docs or config; shell-side writes (`sed -i`) are an open gap `bash-write-guard.js` lets through.
- Everything fail-opens on an unreadable transcript or unknown session model, except Fable, which **fails CLOSED**. `[tier-override: <why>]` lifts any denial deliberately, except a worker reaching for Fable, which is unconditional.

## Principle

Use the cheapest tier whose oracle is strong enough for the decision; pay for a higher tier only where a wrong answer is expensive to discover later.
